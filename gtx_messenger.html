Production-Grade Security Rules (`firestore.rules` & `storage.rules`) Copy and paste these rules into your Firebase Console under Firestore Database → Rules and Storage → Rules. They enforce ownership verification, prevent identity spoofing, and ensure only conversation participants can read or send messages.
firestore.rules 
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isSignedIn() {
      return request.auth != null;
    }

    function isOwner(uid) {
      return isSignedIn() && request.auth.uid == uid;
    }

    // 1. Main User Accounts (Private email storage - never publicly readable)
    match /users/{userId} {
      allow read, write: if isOwner(userId);
    }

    // 2. Identities Collection
    match /identities/{identityId} {
      // Any authenticated user can read public identities for search & chat headers
      allow read: if isSignedIn();

      // Users can only create identities that belong to their own UID
      allow create: if isSignedIn()
        && request.resource.data.ownerUid == request.auth.uid
        && request.resource.data.username is string
        && request.resource.data.displayName is string;

      // Users can only update or delete identities they own
      allow update, delete: if isSignedIn()
        && resource.data.ownerUid == request.auth.uid
        && request.resource.data.ownerUid == request.auth.uid;
    }

    // 3. Conversations Collection
    match /conversations/{conversationId} {
      allow read: if isSignedIn()
        && request.auth.uid in resource.data.participants;

      allow create: if isSignedIn()
        && request.auth.uid in request.resource.data.participants
        && request.resource.data.participants.size() == 2;

      allow update: if isSignedIn()
        && request.auth.uid in resource.data.participants;

      // 4. Messages Subcollection inside a Conversation
      match /messages/{messageId} {
        allow read: if isSignedIn()
          && request.auth.uid in get(/databases/$(database)/documents/conversations/$(conversationId)).data.participants;

        // Sender must be authenticated, a participant, and own the identity used
        allow create: if isSignedIn()
          && request.auth.uid in get(/databases/$(database)/documents/conversations/$(conversationId)).data.participants
          && request.resource.data.senderUid == request.auth.uid
          && get(/databases/$(database)/documents/identities/$(request.resource.data.senderIdentityId)).data.ownerUid == request.auth.uid;

        // Sender can only soft-delete their own message without altering senderIdentityId
        allow update: if isSignedIn()
          && resource.data.senderUid == request.auth.uid
          && request.resource.data.senderUid == resource.data.senderUid
          && request.resource.data.senderIdentityId == resource.data.senderIdentityId;
      }
    }
  }
}
storage.rules 
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /avatars/{userId}/{allPaths=**} {
      allow read: if request.auth != null;
      allow write: if request.auth != null
                   && request.auth.uid == userId
                   && request.resource.size < 2 * 1024 * 1024
                   && request.resource.contentType.matches('image/.*');
    }
  }
}

Step-by-Step Firebase Setup Guide (Pre-Connected to `gtxmessenger`)

  1. Firebase Configuration: Your exact `gtxmessenger` Firebase credentials are already embedded and initialized in this application.
  2. Enable Email/Password Auth: Open Firebase Console → Authentication → Sign-in method and enable Email/Password.
  3. Create Cloud Firestore Database: Go to Build → Firestore Database, click Create database, and start in production or test mode.
  4. Publish Security Rules: Open the Rules tab in Firestore and paste the `firestore.rules` provided in the previous tab, or during initial testing use: allow read, write: if request.auth != null;
  5. Multi-Folder Export Structure: While everything runs seamlessly in this single file, the JavaScript below is cleanly organized into modular sections (`firebase.js`, `auth.js`, `identities.js`, `chat.js`, `app.js`) so you can split them into separate files anytime.
